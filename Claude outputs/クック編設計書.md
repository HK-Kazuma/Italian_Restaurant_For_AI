**前提**

- 実装コードは含めない。
- 時間の書き方：**U** = 上段1周（いまの設定で30秒）、**L** = 下段1周（60秒 = U の2倍）。

## 1. 現状分析（クックに絞って）

### 強み（活かすべき点）

- ジェットオーブンの芯ができている：上段・下段、3レーン、入口の好きな位置に置く、出口の渋滞、焼いた秒数の合計で決まる焼け具合。
- 「上段2周 = 下段1周」という決まりが、すでに遊びになっている。ハンバーグの「上段を2周」、チキンの「下段のあと上段」は、この決まりの上にそのまま乗る。
- 具材台3台と、その下の棚（2段 × 2山 × 3台 = 12か所）がある。器の山を置く場所は足りている。
- ピザの組み立て（決まった順に、決まった位置にのる）と、下駄に乗せて出す流れがある。鉄板焼きの盛り付けと受け台は、この2つの拡張で作れる。
- 湯煎・パックを重ねて持つ・ボトルで振る、がヒート側にある。スープと仕上げの粉は、同じ仕組みを使える。

### 弱み・課題

1. **焼き時間が器の種類で決め打ち**：ドリア系 = L、ピザ系 = U の2通りしかない。同じ鉄板でも、ハンバーグは U を2回、ミックスグリルは L を1回、という違いを表せない。
2. **「途中で出して手を入れる」がない**：1周目のあとヘラではがして付け合わせをのせ、2周目へ、という段階を持てない。
3. **器が2種類だけ**：焼成パッド（普通・大きめ）、ハンバーグの鉄板、目玉焼きの鉄板、鉄のスープ皿がない。
4. **手が1本**：熱い器をやっとこでつかみ、もう片方の手で受け台を用意する、という実際の動きができない。出口の皿を素手で取っている。
5. **ストックの概念がない**：袋から出す、下調理してためておく（ポテト）、という準備の仕事がない。
6. **湯煎器がヒート側にしかない**：スープのたびに厨房を横断することになる。
7. **メニューが2品で、iPad の一覧が1列**：25品になると、今の並べ方では探せない。

### プレイヤー視点での主な不満点の推測

- 「クックは流して待つだけ」。段の選び方と、途中で手を入れる品がないので、ヒートのような段取りの面白さがまだない。
- 「熱い鉄板を素手で持つのは変」。実際に働いている人ほど気になる。
- 「どの皿がどの料理か分からない」。品が増えると、出口に並んだ器の見分けが要る。

## 2. 深化の方針

- **方向性**：クックを「表に1行足せば1品増える」作りに直したうえで、実際の手順（段と周回、ヘラ、やっとこ、下調理、仕上げ）を25品ぶん入れる。ヒートの面白さが「待ち時間をどう埋めるか」なら、クックは「どの段に、どの順で流し、出口をどうさばくか」にする。
- **優先軸**：
  1. 実際の手順の再現（段・周回・器・仕上げ）
  2. 品が増えても迷わない視認性（器の見分け、メニューの一覧）
  3. 既存のヒートとテストを壊さないこと
  4. 軽さ（器と具はすべてコードで生成。写真は使わない）

### 4.1 C1 焼き物の表と「段階焼き」

- **目的**：品ごとの「どの段を何周」「途中で何をするか」を、コードの分岐ではなく表で決める。
- **現状の問題**：必要な焼き時間が器の種類で決まる（`bakeNeed`）。途中で出して手を入れる段階を持てない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 新規ファイル `bake.ts` に、4.0 の表を置く。1品は「段階」の並びで表す。1つの段階は、①流す前にのせる物（種類・数・のせる位置）、②流す前に必要な手入れ（ヘラではがす、など）、③必要な焼き時間（U の何倍か）、の3つを持つ。段階の後ろに「仕上げ」（受け台、ソース、振る物、のせる物）を持つ。
    - 焼け具合は、段階ごとに数える。いまの段階で焼いた秒数が、必要な時間ちょうどで「焼き上がり」、足りなければ「生焼け」、1.25倍を超えたら「焦げ」（既存の決まりのまま）。段階が終わると、秒数を0に戻して次の段階へ進む。
    - 例：ハンバーグの1回目は U。ここで下段に流すと60秒で、37.5秒を超えるので焦げる。チキンの1回目は L。上段を2周しても焼き上がる（既存の「上段2周 = 下段1周」と同じ）。
    - 流すときの判定：器の種類・中身・段階から、当てはまる品を表から探す。当てはまる品がなければ流せず、「この中身の料理はない」と出す（IH の「組み合わせ違い」と同じ考え方）。当てはまる品が複数あるとき（ハンバーグ・イタリアン・ディアボラ風の1回目は同じ中身）は、必要な時間が同じなので、そのまま流す。
    - 入れすぎの防止：器には、その器を使うどの品よりも多くは入らない（焼成パッドにシュリンプは9つまで）。足りないときは流せない。数え間違いは「流せない」で気づく。
    - 提供の判定：最後の段階が焼き上がりで、仕上げがそろっていて、同じ品の伝票があれば提供できる。伝票がなければ注文ミス（−30）。
    - 既存のドリアとピザは、表に同じ値（ドリア = 1段階・L、ピザ = 1段階・U）を書いて、動きを変えない。
  - UI/UXの変更点
    - 入口のヒント：「左クリック：上段に流す（ハンバーグ 1回目。約30秒 → 焼き上がり）」のように、品名・何回目か・結果を出す。段を間違えているときは「→ 焦げる」「→ 生焼け」と出す（既存の出し方の拡張）。
    - 出口の器のラベル：品名と段階を出す（「ハンバーグ 1回目 焼き上がり → ヘラではがす」）。
  - データ構造の変更点
    - 手に持つ焼き皿（`Item` の `bakeDish`）と、ベルトの上の皿（`OvenDish`）に、①中身（のせた物と数）、②いまの段階の番号、③済ませた手入れ、④済ませた仕上げ、を追加。既存の `cooked` は「いまの段階で焼いた秒数」として使う。
    - 既存の `pizza`（生地・ソース・チーズ・モッツァレラ）は残す。新しい品は、新しい「中身」の項目を使う。
    - `MenuItem` の `form` は「焼き物」の1種類にまとめ、どの品かは `bake.ts` の表を id で引く（深化設計書 4.4 の `doria`・`pizza` の2種類の案を、これで置き換える）。
- **実装時の注意点・エッジケース**：
  - 表の整合性をテストで縛る：①同じ器・同じ中身・同じ段階で当てはまる品どうしは、必要な時間が同じ、②必要な時間は U の整数倍、③ある品の流す前の中身が、同じ器の別の品の途中の中身と区別できる。
  - `oven.test.ts` と `pizza.test.ts` の期待値は変えない。先に「既存の2品の結果が今と同じ」ことを確かめるテストを足してから、焼け具合の計算を直す。既存の関数（`bakeState` など）は残し、中で新しい計算を呼ぶ形にする。
  - 段階の途中で生焼けのまま取り出した器は、もう一度流せる（秒数は合計）。焦げたら、どの段階でも捨てる。
  - 出口がいっぱいで本体の中で待っても、焼いた秒数は増えない（既存の決まり。1周ぶんを足す方式）。
- **受け入れ条件**：
  - ハンバーグを、上段 → ヘラ → 付け合わせ → 上段で流すと焼き上がる。1回目を下段に流すと焦げる。
  - チキンを、下段 → ヘラ → 付け合わせ → 上段で流すと焼き上がる。1回目を上段2周にしても焼き上がる。
  - シュリンプ8つの焼成パッドは流せない。10個目は入らない。
  - `game.ts` に、品の名前で分ける分岐がない（表を1行足すだけで品が増える）。
  - 既存のテストが無修正で通る。

### 4.2 C2 器の追加と作業枠

- **目的**：新しい器を、既存のベルトの決まりを増やさずに使えるようにする。盛り付けと仕上げの場所を作る。
- **現状の問題**：器はドリア系とピザ系だけ。盛り付けの場所は、ピザ用の丸い置き場2つだけ。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 器の寸法は「3列系」と「2列系」の2通りだけにする。新しい器は、必ずどちらかの寸法を使う。レーンと置き場の計算は、器の種類ではなく寸法の系統で決める。

      | 器 | 寸法の系統 | 使う品 |
      |---|---|---|
      | ドリア皿（グラタン皿） | 3列系（既存） | ドリア4品、ポテトのグリル、チョリソー、辛味チキン |
      | ピザの鉄板 | 2列系（既存） | ピザ4品 |
      | 焼成パッド | 3列系 | シュリンプ、フォッカチオ5品 |
      | 大きめの焼成パッド | 2列系 | ポテトの下調理 |
      | ハンバーグの鉄板 | 3列系（仮） | 肉料理6品 |
      | 目玉焼き鉄板 | 3列系（仮） | 目玉焼き |
      | 鉄のスープ皿 | 3列系（仮） | スープ2品 |

    - 作業枠：1台目の具材台（オーブンの入口の隣）の、部屋の中央側の縁に、3列系の器を置く枠を3つ並べる（器の長い辺を左右に向ける）。ここで、盛り付け・ヘラではがす・仕上げをする。2列系の器（大きめの焼成パッド）は、既存のピザの組み立て台2つに置く。
    - 作業枠には、器だけでなく、受け台（下駄・板）と小皿も置ける。受け台の上に器を乗せて、ソースや粉をかける。
    - 盛り付けの位置は自動：具をのせると、表に書いた位置に入る（ピザのモッツァレラと同じ考え方）。プレイヤーが位置を選ぶことはない。
    - 棚の割り当て（具材台の下、12か所）：
      - 1台目：ミラノドリア、焼きチーズミラノドリア、たらこのドリア、たらこのグラタン
      - 2台目：空のドリア皿、焼成パッド、大きめの焼成パッド、鉄のスープ皿
      - 3台目：ハンバーグの鉄板、目玉焼き鉄板、（空き2か所）
    - 板（鉄板用の受け台）の山と小皿の山は、下駄の山の隣（左の台の、提供台より壁側）に置く。
    - 1台目の天板にあるテスト用の焼き皿の山は、なくす（ドリアは棚の山から取る。ピザのテスト用の山は開発時だけ）。
  - UI/UXの変更点
    - 器の見た目：焼成パッドは、添付の写真のような浅いステンレスの角バット。大きめは同じ形で一回り大きい。ハンバーグの鉄板は黒い楕円、目玉焼き鉄板は黒い長方形にくぼみ2つ、スープ皿は黒い深い丸。山は、器ごとに形と色で見分けられるようにする。
    - 棚の山には、品名のラベルを出す（ドリア4品は見た目が近いため）。
  - データ構造の変更点

### 4.4 C4 道具の手（やっとこ・ヘラ）

- **目的**：熱い器はやっとこでつかむ。右手に道具、左手に受け台、という実際の両手の使い方を入れる。
- **現状の問題**：手は1本（`state.hand`）。出口の熱い皿を素手で取っている。「持てるのは1つだけ」はヒートの土台なので、これを壊さずに両手にする必要がある。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 手を2つに分ける。**左手** = 今までの手（`state.hand`）。決まりも操作（左クリック）も変えない。**道具の手** = やっとこかヘラだけを持つ、新しい手。
    - 道具の手の操作は、新しいキー **F**（`input.ts` で空いている。使えるキーは今 WASD と E だけ）。
    - 道具は、1台目の具材台の縁のフックに掛かっている。フックに視点を合わせて F で取る・戻す・持ち替える（手が届く距離は5mあるので、遠くからでも持ち替えられる）。
    - **熱い器**：一度でもオーブンを通った器は熱い。素手（左クリック）では取れず、「熱い！ やっとこでつかむ（F）」と出す。空になって山に戻した器は、冷めた扱いにする。
    - **やっとこ**：F で、出口の器・作業枠の熱い器をつかむ。つかんだまま、F で置く（作業枠、入口のベルト、作業枠に置いた受け台の上、器の山）。つかめるのは1つ。
    - **手元で合わせる**：やっとこの器と、左手の受け台が合う組み合わせでそろったら、その場で器が受け台に乗る（やっとこは空に戻る）。順番はどちらが先でもよい。
      - 焼き上がったドリア皿 ＋ 左手の下駄 → 左手が「下駄に乗ったドリア」になる
      - 最後まで焼けた鉄板・スープ皿 ＋ 左手の板 → 左手が「板に乗った鉄板」になる
      - 焼き上がったピザの鉄板 ＋ 左手のピザのお皿 → 左手が「ピザの入ったお皿」、やっとこに空の鉄板が残る
      - 焼き上がった焼成パッド ＋ 左手の小皿 → 左手が「料理ののった小皿」、やっとこに空のパッドが残る
    - 途中の段階の器（ハンバーグの1回目のあと、など）は、受け台を持っていても乗らない。
    - **ヘラ**：F で、作業枠の鉄板を「はがす」（1回）。F で、目玉焼き鉄板から目玉焼きを1つすくい、仕上げ中のハンバーグに F でのせる。
    - **捨てる**（右クリック）：左手の物が先。左手が空なら、やっとこの器を捨てる。道具そのものは捨てられない。
    - **入門の扱い**：新しい設定値 `hotHandling` を足す。トライアルクルーはオフ（素手で取れる。ヘラの作業は、手が空のとき左クリック）。リーディング・アソシエイト・練習キッチンはオン。
  - UI/UXの変更点
    - 画面の見た目：左手の物は画面の左下、道具は右下に出す。道具を持っていないときは、今の位置のまま。
    - 画面下の手持ちの表示を2つに分ける（「左手：下駄」「道具：やっとこ（ミラノドリア）」）。
    - 十字の下のヒントに、F でできることを足す（「F：やっとこでつかむ」）。左クリックのヒントと2行で出す。
    - ハイライトは、左クリックか F のどちらかでできることがあれば光らせる。
    - やっとこの見た目は、添付の写真のような、先が平たくつかめる金属のはさみ。つかんだ器は、やっとこの先に付けて出す。
  - データ構造の変更点
    - `GameState` に道具の手を追加：何も持っていない / やっとこ（つかんでいる器、または空）/ ヘラ（すくった目玉焼き、または空）。
    - `Target` に、道具のフックを追加。
    - `GameConfig` に `hotHandling` を追加。`DEFAULT_CONFIG` ではオフにし（既存のテストは素手で出口の皿を取っているため）、`main.ts` が使う本番用の設定でオンにする。トライアルは `difficulty.ts` でオフに上書きする。
- **実装時の注意点・エッジケース**：
  - 焼き皿についての分岐（出口で取る、入口に置く、下駄に乗せる、お皿に移す、山に戻す）を、「どちらの手が持っているか」を引数に取る形に切り出し、左クリックと F の両方から同じ処理を呼ぶ。同じ決まりを2か所に書かない。
  - F も、左クリックと同じく「できることを返す」形（`planInteract` と同じ作り）にする。ハイライトと実行が同じ分岐を通る、という前提を保つ。
  - 既存の「下駄を持って出口を左クリックすると、ドリアが下駄に乗る」は、`hotHandling` がオフのときだけ残す。オンのときは、やっとこで F。
  - 鍋投げ・冷蔵庫の置き直し・iPad など、左手と右クリックの既存の決まりは変えない。やっとこを持っていても鍋は投げられる。
  - 練習からゲームに入るとき、道具はフックに戻す。
  - iPad の「操作説明」に、F を足す。
- **受け入れ条件**：
  - 左手に下駄、やっとこで出口のドリアを F でつかむと、左手が「下駄に乗ったドリア」になり、そのまま提供できる。先にやっとこでつかんでから下駄を取っても、同じ結果になる。

  - F でできることがある物だけが光り、F を押すとそのとおりに動く（光るのに反応しない、がない）。

## 6. 実装モデルへの引き継ぎメモ

### 特に注意してほしい点

- **品の名前で分岐を書かない**。段・周回・中身・仕上げは、すべて `bake.ts` の表から引く。`game.ts` に「ハンバーグなら」という条件が出てきたら、設計から外れている。
- **「仮」の値は、表と設定値にだけ置く**。確認事項の答えが変わっても、表の値を直すだけで済むようにする。
- **左手（`state.hand`）の決まりを変えない**。道具の手は、横に足す。ヒートの操作とテストは、道具の手を知らないまま動く。
- **F も「できることを返す」形にする**。左クリックと F で、同じ焼き皿の決まりを2回書かない。
- **写真は色と盛り付けの参考だけ**。添付の袋の写真には実在のロゴがある。ゲームの袋のラベルは、屋号のロゴと品名にする。メニュー表の写真も、テクスチャやサムネに使わない。

### 既存コードとの整合性で気をつけること

- `oven.test.ts`（539行）・`pizza.test.ts`（704行）・`geta.test.ts` の期待値を変えない。`DEFAULT_CONFIG` の `hotHandling` をオフにしておくのは、このため。
- `Target` と `Item` の既存の種類名を変えない。足すのはよい。
- 作業台（`prep`）に置く物は、`PREP_FIXTURES` に登録する。登録を忘れると、ピザのお皿が容器にめり込んで置ける。
- 見た目の違い（品、段階、はがしたか、ソース、逆さま）を足したら、`itemSignature` と `pizzaSignature` に反映する。
- 湯煎器・冷蔵庫と同じく、2台目の設備は「どちらか」を省略できる項目で足し、省略したら1台目にする。
- 新しい設定値は `config.ts`、難易度の違いは `difficulty.ts` に置く。
- 仕様にない判断をしたら、README の「仕様にない判断」に足す。要件定義書の「ドリア枠」「ピザ枠」も、4.0 の表に合わせて直す。

### 避けてほしい実装方針

- 手を「右手・左手のどちらにも何でも持てる」形に広げること。ヒートの「持てるのは1つ」が崩れ、既存の操作の表（`planInteract`）を全部書き直すことになる。道具の手が持てるのは、やっとことヘラだけ。
- 器ごとに、新しいレーンの決まりを作ること。寸法は3列系と2列系の2通りだけ。
- 盛り付けの位置を、プレイヤーに選ばせること。位置は表で決まり、自動で入る。
- 品ごとに、チュートリアルの工程を手で書くこと（クックは表から作る）。
- 冷凍の袋やストックを、数に限りのある在庫にすること（ポテト以外）。補充の仕事は、ポテトの下調理だけにする。
