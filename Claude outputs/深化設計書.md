# イタリアンレストランシミュレーター 深化設計書

2026-11-13 作成 / 対象：`HK-Kazuma/Italian_Restaurant` の main（2026-11-10、PR #10 マージ時点）

**前提**
- この設計は、GitHub 上の main を読んで書いた。ローカルにある未プッシュの変更は反映していない。
- 読んだのは README・要件定義書・ロジック層の主要ファイル・`scene.ts` の構造と描画設定。ゲームを実際に動かして画面を見てはいないので、見た目の評価はコードからの判断。
- 実装コードは含めない。型名・ファイル名・設定値の名前は、実装者が迷わないよう既存の名前で書く。

---

## 1. 現状分析

### 強み（活かすべき点）

- **ロジックと描画が分かれている**：`game.ts` 以下は Three.js を使わず、テストが21ファイルある。見た目を作り替えてもルールは壊れない。今回の「見た目をリアルに」は、この分離のおかげで安全に進められる。
- **実務の段取りが、すでにゲームになっている**：茹で麺器の猶予30秒とショート茹で、既定のソースがそろうと自動で始まる加熱、湯煎、1台しかない洗浄機の渋滞、トレー置き場、冷蔵庫の置き直し。15品が動く。これがこのゲームの「らしさ」の中心。
- **クックの土台が動いている**：ジェットオーブン（上段・下段、レーン、出口の渋滞）、焼け具合4段階、下駄、ピザの組み立てまで実装済み。
- **設定値が外に出ている**：`config.ts`・`difficulty.ts`・`layout.ts`。数値の調整と難易度の追加がコードの分岐なしでできる。
- **状態を見て進む仕組み**：チュートリアルは `GameState` だけを見て進む。`game.ts` にチュートリアル用の分岐がない。この方式は、音や演出にもそのまま使える。
- **軽い**：依存は three と firebase だけ。3Dモデルのファイルは0で、見た目はすべてコードで生成している。
- **屋号がオリジナル**：「ドリアーノ田中's Kitchen」のロゴ。公開しても実在の店名を使わない形になっている。

### 弱み・課題

1. **質感がない**：全メッシュが `MeshLambertMaterial`（`scene.ts` の `mat()`）。ライトは半球1つと平行1つ、影なし、トーンマッピングなし、環境の映り込みなし。ステンレスがグレーの樹脂に見え、皿や鍋が台から浮いて見える。床・壁・天井は単色の箱。
2. **厨房らしさを作る背景がない**：換気フード、巾木、タイルの目地、排水溝、掲示物など、操作しないが「厨房だ」と感じさせる物がない。
3. **音がゼロ**：音を鳴らすコードがない。要件定義書が狙う「画面を見なくても気づける」は、いまは湯気だけ。
4. **鍋の焦げが未実装**：`PotHeat` に焦げの状態がなく、加熱は「完成」で止まる。IHは待つだけで、失敗の危険がない。
5. **クックが採点につながっていない**：`Station` は `pasta` と `salad` だけ。`MENU` にドリアもピザもなく、提供しても「採点なし」。ドリアは「テスト用の焼き皿の山」から取る。オーブンの時間（30秒・60秒）はテスト用の仮の値。ハンバーグ・グリル系は器も工程も未定義。
6. **鍋投げに目的がない**：投げる・跳ねる・拾うは動くが、当てる相手も得点もない。
7. **リザルトが総合点だけ**：`served`・`mistakes`・`maxCombo` は数えているが、品ごとの内訳や評価がない。
8. **手応えが文字頼み**：操作の結果は、ほぼトーストの文章で伝えている。
9. **`scene.ts` が3,360行**：マテリアルを呼び出しのたびに新しく作っていて、見た目の一括調整ができない。ハイライト（`interaction.ts`）は「メッシュごとに別のマテリアル」を前提に、発光色を直接書き換えている。
10. **名前のラベルが常に出ている**：設備名のスプライトが常時見えていて、デバッグ画面のように見える。

### プレイヤー視点での主な不満点の推測

- 「積み木の厨房に見える」。ステンレスの光り方、料理のツヤ、接地の影がないので、作業は本物なのに画が安い。
- 「麺が上がったのに気づかなかった」。音がないので、常に全部を目で見回す必要がある。
- 「ソースは火にかけたら放置でいい」。焦げないので、IHの段取りに緊張がない。
- 「ドリアを焼いても点が入らない」。クックの設備は触れるのに、遊びとして閉じていない。
- 「鍋を投げられるのは面白いが、10秒で飽きる」。
- 「5分終わって数字が出るだけ」。何がうまくいって何が遅かったのかが分からず、次の1回の目標が立たない。

## 2. 深化の方針

- **方向性**：「本物の厨房の段取り」という芯は変えず、①見た目と音を業務用厨房の質感まで引き上げ、②クック（焼き）を採点まで通し、③ボケ要素は本編の採点を壊さない別の層として足す。
- **優先軸**（上から順）：
  1. 質感と視認性（モデルファイルを増やさず、軽さを保つ）
  2. クックポジションの完成
  3. 手応え（音・演出・焦げ）
  4. ボケ要素
  5. リプレイ性（リザルトの内訳・称号）

## 4. 各改善項目の詳細設計

### 4.1 質感の土台（マテリアル・ライト・トーンマッピング）

- **目的**：モデルファイルを1つも足さずに、素材の違い（金属・陶器・樹脂・食材）が見て分かる画にする。
- **現状の問題**：
  - `mat(color)` が呼ばれるたびに `MeshLambertMaterial` を新しく作る。Lambert には光沢がなく、金属を表現できない。
  - 環境の映り込みがないので、金属にしても真っ黒になる。
  - トーンマッピングが未設定で、明るい面が白く飛ぶか、全体がのっぺりする。
  - 影がなく、物が台に「置いてある」ように見えない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 新規ファイル `materials.ts`（描画層）に、素材の一覧表を置く。`scene.ts` の中で色から直接マテリアルを作るのをやめ、この表から取る。
    - 素材は `MeshStandardMaterial` を基本にする。目安の値（最終値はスクリーンショットを見て決める）：

      | 素材名 | 使う場所 | 金属度 | 粗さ | 備考 |
      |---|---|---|---|---|
      | ステンレス（明） | 天板、冷蔵庫の扉、フード、オーブン本体、鍋 | 1.0 | 0.38 | 横方向の細い筋（ヘアライン）を256×256のキャンバスで作り、粗さのテクスチャに使う |
      | ステンレス（暗） | 脚、巾木、棚の支柱 | 1.0 | 0.55 | |
      | 陶器 | 皿、スープ皿、リム小皿、ピザ皿 | 0 | 0.22 | |
      | 樹脂 | トレー、ケース、コンテナ、ボトル | 0 | 0.6 | |
      | 黒ガラス | IHの天板、iPadのふち | 0 | 0.08 | |
      | 木 | 下駄、木の皿 | 0 | 0.75 | 既存の木目テクスチャを使う |
      | ソース類 | 鍋・皿の上のソース、ドレッシング | 0 | 0.3〜0.4 | ツヤを出す |
      | 葉物・麺・肉 | サラダ、麺、チキン、エビ | 0 | 0.7 | |
      | 粉物 | 粉チーズ、パプリカ、のり | 0 | 0.95 | |
      | 水面 | 茹で麺器、湯煎 | 0 | 0.05 | 半透明（不透明度0.55前後） |

    - 環境の映り込み：three に同梱の「室内の環境」を起動時に1回だけ映り込み用に変換し、シーン全体の環境に設定する。画像ファイルのダウンロードはしない。強さは0.5前後。背景色は今の単色のまま（部屋は閉じているので外は見えない）。
    - ライト：半球ライトを今の1.5から0.6前後へ、平行ライトを1.6から1.0前後へ下げる（環境の映り込みが明るさを足すため）。ライトの数は増やさない。
    - トーンマッピング：色がくすみにくい「ニュートラル」を第一候補にする（ACESは料理の赤と緑が沈む）。露出は1.0。
    - トーンマッピングの対象から外す物：置き場の緑の印、チュートリアルの矢印、ラベルのスプライト、iPadの画面、看板。色が変わると、案内の意味（緑 = 置ける、赤 = 置けない）が読みにくくなる。
    - 接地の影（標準の画質）：円形のぼかしを64×64のキャンバスで作り、半透明の板として、皿・鍋・ボトル・トレー・缶・焼き皿・下駄の底に付ける。台の面から0.002m浮かせ、奥行きの書き込みはしない。
    - 境目の暗がり：台と壁、台と床の境目に、幅0.08m・不透明度0.25前後の暗いグラデーションの帯を置く。
    - 後処理（画面全体にかける効果）は使わない。
  - UI/UXの変更点
    - 開発時だけ、画面の隅に描画回数・三角形の数・1フレームの時間を出す（`import.meta.env.DEV` のとき。`main.ts` に既存の開発用の分岐がある）。
  - データ構造の変更点
    - なし（`GameState` は触らない）。
- **実装時の注意点・エッジケース**：
  - **ハイライトが壊れる**：`interaction.ts` の `setEmissive` は、狙った物の下にあるメッシュ全部の発光色を書き換える。マテリアルを共有すると、同じ素材の別の物まで一緒に光る。対策は「操作できる物（`setTarget` を付けた根）の下のマテリアルだけ、その根ごとに複製して持たせる」。背景の物は共有のままでよい。
  - `setEmissive` は発光色を持たないマテリアル（`MeshBasicMaterial`）に当たると落ちる。狙える物の下に基本マテリアルを置く場合は、書き換えの対象から外す。
  - 皿や手持ちの見た目は、中身の署名が変わるたびに作り直される（`ItemView`）。作り直しのたびに複製したマテリアルを捨てているか（`disposeTree`）を確認する。共有マテリアルを誤って捨てない。
  - 半透明の物（水面、置く前の薄い見本、湯気）の前後関係が崩れやすい。水面は奥行きの書き込みをしない。
  - 質感を変える前に、次の3場面で描画回数・三角形の数・フレーム時間を記録する：①初期視点、②冷蔵庫3台を開けた状態、③皿3枚・鍋4つ・伝票10枚の最も忙しい場面。
- **受け入れ条件**：
  - 初期視点のスクリーンショットで、天板に天井の明るさが映り込み、皿に白いハイライトが出ている。
  - 皿・鍋・ボトルの底に影があり、台から浮いて見えない。
  - 狙った物だけが緑に光り、同じ素材の別の物は光らない（鍋置き場の鍋5つで確認）。
  - 置き場の緑と赤、チュートリアルの黄色い矢印の色が、変更前と同じに見える。
  - 上の3場面で、描画回数の増加が記録値の25%以内、内蔵GPUのノートPC（1920×1080、画素比1）で場面③が毎秒60コマを保つ。
  - 画像ファイルの追加が0、ビルド後のJavaScriptの増加がgzipで60KB以内。
  - `npm test` と `npm run build` が通る。

### 4.2 厨房の作り込み（床・壁・設備・小物）

- **目的**：操作する物の位置は1cmも動かさずに、背景と設備の外観だけで「業務用の厨房」に見せる。
- **現状の問題**：床・壁・天井が単色の箱。設備は角が鋭い箱の組み合わせで、取っ手・脚・継ぎ目がない。
- **具体的な変更内容**：
  - 機能・挙動の変更点（すべて見た目だけ。当たり判定と座標は変えない）
    - 床：0.4m角のタイル（グレーベージュ、目地は4mmの暗色）を512×512のキャンバスで作り、繰り返して貼る。IHの前に排水溝のふた（格子）を1本。
    - 壁：白いパネル（0.9mごとに縦の継ぎ目）と、床ぎわに高さ0.1mの黒い巾木。
    - 天井：明るいグレーの0.6m格子に変え、作業ラインの真上に、発光する白い板（蛍光灯）を3〜4本。板は光って見えるだけで、ライトは足さない。
    - 換気フード：IHと茹で麺器の上。下端の高さは2.45m以上（生麺の棚2.15mとスープ皿の棚を隠さない）。前面に0.25mの垂れ壁。
    - 設備の面取り：天板・冷蔵庫の本体と扉・オーブン本体・洗浄機だけ、角を半径0.012mで丸める（three 同梱の角丸の箱を使う）。小さい部品は箱のまま。
    - 設備の細部：扉の縦の取っ手、冷蔵庫の扉の黒いパッキンの線と緑の温度表示、台の脚（床との間に0.15mの隙間）。
    - 茹で麺器と湯煎：半透明の湯面をゆっくり流す。茹でている口は、小さな泡を20個ほど（同じ形をまとめて描く方式で）出す。
    - IH：黒ガラスの天板に口ごとのリング。加熱中は、既存の色分け（`BURNER_COLORS`）でリングを発光させる。
    - ジェットオーブン：ベルトを網目のテクスチャにして流す。流れる速さは `beltSpeed` と一致させる（皿とベルトがずれて見えないように）。入口と出口の奥を赤橙に発光させる。
    - 操作しない小物：壁時計（針が残り時間を指す。ゲームの情報として使える）、手洗い場、消火器、伝票のプリンター、掲示物（「鍋を投げない」の貼り紙など、ボケの置き場）。
    - 提供台の近くの壁に「デシャップ窓」（4.7で使う）。位置は `layout.ts` に定数 `CLAIM_WINDOW` として足す（中心の座標、幅1.0m、下端1.05m、上端1.95m）。壁の箱を窓の上下左右に分けて作る。歩ける範囲（`World` の `bounds`）は変えない。
  - UI/UXの変更点
    - 壁時計は、練習キッチンでは実際の時刻、ゲーム中は残り時間（5分で1周）を指す。
  - データ構造の変更点
    - `layout.ts` に `CLAIM_WINDOW` を追加。ほかは変更なし。
- **実装時の注意点・エッジケース**：
  - 視線の判定は `interactables` に入れた物だけを見る。つまり、装飾は視線を遮らないが、見た目では手前に被って「見えないのに光る・取れる」が起きる。初期位置から、すべての取り出し元と置き場が装飾に隠れていないかを確認する。
  - 装飾を `interactables` と `world.obstacles` に入れない。入れると、歩ける範囲と投げた鍋の跳ね返りが変わり、`world.test.ts`・`throw.test.ts` の前提が変わる。
  - 部屋は、設備が壁からはみ出すと右と奥に自動で広がる（`createKitchen` の先頭）。床のタイル・天井の格子・巾木・フードは、広がった後の寸法から計算する。
  - デシャップ窓の位置は、①初期位置から見える、②ジェットオーブンと具材台に重ならない、③提供台（`SERVE_PASS`）から2.5m以内、の3つを満たす壁面にする。
  - 泡や小物で同じ形を多数置くときは、1つずつメッシュを足さず、まとめて描く方式にする。
- **受け入れ条件**：
  - `layout.ts` の既存の座標、`world.obstacles` の中身が変更前と同じ（差分で確認）。
  - 初期位置から360度見回して、単色の大きな面（床・壁・天井）が残っていない。
  - 既存15品のチュートリアルが、矢印の位置も含めて変更前と同じに進む。
  - 4.1の性能の条件を引き続き満たす。

### 4.3 料理と器の見た目

- **目的**：完成した皿が「おいしそう」に見え、焼け具合が色で判断できる。
- **現状の問題**：料理は色のついた形の集まりで、ツヤと焼き色がない。焼け具合は色の違いだけで、焼き上がりと生焼けの差が小さい。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 皿：陶器の素材にし、ふちに厚みを付ける。
    - パスタ：既存の麺の筋のテクスチャを、凹凸にも使う（テクスチャは増やさない）。ソースは粗さ0.35でツヤを出す。
    - ドリア：表面のテクスチャを焼け具合ごとに4種類、128×128のキャンバスで作って使い回す。焼く前 = 白いソースの下にミートソースの赤が透ける。生焼け = 薄い黄色。焼き上がり = きつね色の斑点と、ふちの焦げ茶。焦げ = 黒茶。`buildDoriaDish` の引数は変えない。
    - ピザ：焼き上がりで、チーズを「粒」から「溶けた1枚の層」に切り替える。モッツァレラは高さ0.4倍・半径1.3倍の平たい円盤にする。生地のふちに焼き色。
    - 焼きたての湯気：出口から取った焼き皿は、手に持ってから5秒間、既存の `Steam` を出す。見た目だけで、状態は増やさない（手持ちの署名が変わった時刻を描画側で覚える）。
    - サラダ：レタスの葉に明るい緑と濃い緑の2色を混ぜ、ドレッシングはツヤのある素材にする。
  - UI/UXの変更点
    - なし。
  - データ構造の変更点
    - なし。
- **実装時の注意点・エッジケース**：
  - 見た目の違いを増やしたら、`itemSignature` に必ず反映する。反映しないと、状態が変わっても作り直されない。
  - 乱数は、既存の種つきの乱数（`seeded`・`hashId`）を使う。作り直すたびに具の位置が変わると、ちらついて見える。
  - 参考にするメニュー写真は、色と盛り付けの参考にとどめる。写真そのものをテクスチャとして貼らない（容量が増えるうえ、公開サイトに他者の写真を載せることになる）。
- **受け入れ条件**：
  - ドリアの4つの焼け具合を並べたスクリーンショットで、ラベルを隠しても4つを言い当てられる。
  - 焼き上がったピザのチーズが1枚につながって見える。
  - 同じ皿を持ち上げて置き直しても、具の位置が変わらない。
  - 追加したキャンバステクスチャの合計が、縦横512以下のものだけで10枚以内。

### 4.4 クックの採点接続とポジション選択

- **目的**：すでに動いているドリアとピザを、伝票・採点・ランキング・チュートリアルにつなぐ。ヒートとクックを選んで遊べるようにする。

  - 機能・挙動の変更点

### 4.5 効果音と環境音

- **目的**：麺の上がり、ソースの完成、焼き上がり、伝票の到着を、耳で分かるようにする。厨房の空気を音で作る。
- **現状の問題**：音がない。5つ以上の設備を、目だけで見張る必要がある。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 新規ファイル `audio.ts`（描画・入力の層）。チュートリアルと同じく、毎フレーム `GameState` の前回との差を見て音を鳴らす。`game.ts` に音のための分岐は足さない。
    - 音はブラウザの音声機能で合成する（発振音・ノイズ・フィルター・音量の変化）。音声ファイルは0から始める。
    - 一度だけ鳴る音：

      | きっかけ（状態の変化） | 音 |
      |---|---|
      | 茹で麺器が「茹で中」から「上がった」になった | 電子音3回（ピピピ） |
      | 茹で麺器が「のびかけ」になった | 低い警告音2回 |
      | 鍋が「加熱中」から「完成」になった | 短いチャイム1回 |
      | オーブンの出口に出てきた皿の数が増えた | 長めの電子音1回 |
      | 洗浄機の残り時間が0になった | 短い電子音1回 |
      | 伝票の数が増えた | プリンターの印字音（短いノイズ） |
      | `served` が増えた | 明るい2音 |
      | `mistakes` が増えた | 低いブザー |
      | 手持ちが変わった | 小さなクリック音（取る・置くで高さを変える） |
      | 投げた鍋が床・台・壁に当たった | 金属音（当たる速さで音量を変える） |

    - 鳴り続ける音：換気扇の低いノイズ（常時、小さく）、茹で麺器の沸く音（茹でている口の数で音量が変わる）、IHの煮える音（加熱中の鍋の数で変わる）、オーブンのベルトの音。
    - 方向：音の出る設備の位置と、視点の向きから、左右の振り分けと距離による音量を決める。後ろの茹で麺器の音が、後ろから聞こえる。
    - 止める条件：一時停止（Escで視点のロックが外れたとき）と、タブが隠れたときは、すべての音を止める。iPadを開いている間は鳴らし続ける（厨房の時間は進んでいるため）。
  - UI/UXの変更点
    - iPad「設定」に「音量」（0〜1、0.05刻み、既定0.7）を足す。0で無音。
  - データ構造の変更点
    - `Settings` に `masterVolume` を追加（既存の保存キーに一緒に保存）。
    - 鍋の当たった音のために、`ThrownPot` に「当たった回数」を数える項目を1つ足す（`throw.ts` の跳ね返りの処理で増やす。音の側は、数が増えたら鳴らす）。
- **実装時の注意点・エッジケース**：
  - ブラウザは、利用者の操作より前に音を出せない。最初のクリック（視点のロックを取るクリック）で音声を開始する。それより前には何も鳴らさない。
  - 練習からゲームへ切り替わるとき、状態が丸ごと作り直される。作り直しの直後の1フレームは「差」を見ない（伝票が0から増えた、などの誤検知で一斉に鳴るのを防ぐ）。
  - 同じ音が同じフレームに複数起きたら1回にまとめる（茹で麺器4口が同時に上がった場合など）。
  - 既存の設定値は「倍率」として保存されている。`loadSettings` は知らない項目を無視し、足りない項目は既定値にするので、古い保存データでも動くことをテストで確認する。
- **受け入れ条件**：
  - 茹で麺器に背を向けていても、上がったことが音で分かり、左右どちらにあるかが分かる。
  - 最初のクリックより前に音が鳴らない。音量0で完全に無音になる。
  - 一時停止とタブの切り替えで、鳴り続ける音が止まる。
  - 音声ファイルの追加が0。
  - 練習からゲームを始めた瞬間に、音が一斉に鳴らない。

### 4.6 鍋の焦げ

- **目的**：要件定義書にある「放置しすぎると焦げる」を入れ、IHの見張りを段取りの一部にする。
- **現状の問題**：加熱は「完成」で止まる。完成した鍋をいくら置いても何も起きない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - `PotHeat` に「焦げ」を足す。完成した鍋がIHに載っている間だけ、焦げまでの時間が進む（持ち上げると止まる。加熱と同じ決まり）。
    - 焦げるまでの時間は、新しい設定値 `sauceBurnTime`（既定20秒。要件定義書の仮の値）。
    - 麺を入れた鍋（Aパターンで混ぜる前後）は、焦げまでの時間を止める。麺を待っている間に焦げるのは、鍋を降ろしておけば防げる。
    - 焦げた瞬間に、減点 `burnPenalty`（既定20）、コンボが0に戻る、`mistakes` が1増える。
    - 焦げた鍋は、皿にかけられず、具材も足せない。洗浄機で洗うと元に戻る。洗う時間は通常の2倍（新しい設定値 `burntWashFactor`、既定2）。洗浄機の渋滞という既存の緊張につながる。
    - 難易度ごとの上書き：トライアルは40秒、アソシエイトは15秒。
    - チュートリアル中は焦げない（工程の案内どおりに待つだけで失敗しないように）。
  - UI/UXの変更点
    - 焦げまでの時間が半分を過ぎたら、湯気を灰色の煙に変えていく。鍋の中身の色を焦げ茶へ近づける。IHのラベルを「完成」から「焦げそう」に変える。
    - 焦げたら、黒い煙、ラベル「焦げた」、トースト「焦がした！ −20」。
    - 音（4.5がある場合）：煮える音を高く鋭くし、焦げた瞬間に警告音。
  - データ構造の変更点
    - `Pot` に、焦げまでの残り時間を持つ項目を追加。
    - `GameConfig` に `sauceBurnTime`・`burnPenalty`・`burntWashFactor` を追加。
    - `DifficultyDef` の上書きできる設定値を、伝票の項目だけから、`sauceBurnTime` も含む形に広げる。
- **実装時の注意点・エッジケース**：
  - 練習キッチンでも焦げる（練習で覚えるため）。ただし減点はしない（練習はスコアなし）。
  - 既定のソースにならない組み合わせの鍋は、加熱が始まらないので焦げない。
  - `tutorial.ts` の工程の「終わったか」の判定が、鍋の状態が「完成」であることに頼っている箇所を確認する。チュートリアル中は焦げないので、判定は変えなくてよいはず。
  - 焦げた鍋を投げた場合も、鍋の状態はそのまま保つ。
  - README の「未実装：ソースの焦げ」と、「仕様にない判断」の該当行を更新する。
- **受け入れ条件**：
  - 完成した鍋をIHに20秒置くと焦げ、−20・コンボ0になる。10秒で降ろし、また載せると、残り10秒から進む。
  - 焦げた鍋は、洗浄機で10秒洗うと使える。
  - 麺を入れた鍋は焦げない。チュートリアル中は焦げない。
  - `pot.test.ts` に、上の4つのテストがある。

### 4.7 クレーマー客イベント（鍋投げ）

- **目的**：鍋投げに「当てる相手」と「得点」を与える。1ゲームに数回、笑える出来事を起こす。本編の採点は壊さない。
- **現状の問題**：鍋は投げられるが、意味がない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - ゲーム中（練習とチュートリアルを除く）に、デシャップ窓からクレーマー客が上半身を乗り出してくる。
    - 回数：トライアルは最大1回、リーディングは1〜2回、アソシエイトは2〜3回。最初の出現は開始60秒より後、最後の20秒には出ない。出る時刻は、既存の乱数（`rng`）で決める。
    - 流れ：予告2秒（窓の向こうから声と吹き出し）→ 居座り12秒（新しい設定値 `claimDuration`）→ 帰る。
    - 鍋を当てる：飛んでいる鍋が、客の当たり判定に入ったら命中。+20点（`claimHitPoints`）。4m以上離れて当てたら、さらに+10点。「始末書」が1枚増える（得点には影響しない。リザルトで使う）。コンボは増えも減りもしない。
    - 放置：12秒たつと、客は怒って帰る。コンボが0に戻る。減点はしない。
    - 外した鍋は、床か台に落ちる。拾いに行く時間が、そのまま代償になる（既存の動きのまま）。
    - 当たり判定：円柱。中心は窓の中心から厨房の側へ0.25m、半径0.35m、高さ1.0〜1.9m。壁の手前で鍋が止まっても当たる大きさにする。水平に投げて届くのは約3mまでで、それより遠くからは上向きに狙う（投げる速さ6m/s、視点の高さ1.6mから計算）。
    - 当たった鍋は、勢いを3割に落として手前に跳ね返り、窓の下に落ちる。
    - 客は左クリックでは狙えない（`Target` に足さない）。反応するのは投げた鍋だけ。
  - UI/UXの変更点
    - 客の見た目：丸い頭と胴体の、記号的な人形。怒った眉は、キャンバスで描いた顔を貼る。実在の人物に似せない。
    - 吹き出し：ひとことを乱数で選ぶ。文は、差し替えやすいように1つの配列にまとめる。例：「このドリア、熱いんだけど！」「粉チーズ、もっとかけさせて！」「まちがい探しが難しすぎる！」「安すぎて逆に不安なんだけど！」。
    - 命中の演出：金属音、星が散る、客が目を回して窓の下へ沈む。トースト「クレーム対応（物理）+20」。けがの描写はしない。
    - 放置の演出：客が首を振って去る。トースト「クレームを放置した（コンボが切れた）」。
    - 鍋を持っていて客がいる間、ヒントを「右クリック：鍋を投げる（クレーマーに当てると…？）」に変える。
    - 練習キッチンには、同じ場所に「練習用の的」（等身大のパネル）を常に立てる。当てると音と星だけで、点は入らない。
  - データ構造の変更点
    - `GameState` に `customer`（いない / 予告 / 居座り / 命中して退場 / 怒って退場、残り時間、ひとことの番号）を追加。
    - `GameState` に `claimsHit`（命中の数）、`reports`（始末書の数）、次に出る時刻を追加。
    - `GameConfig` に `claimDuration`・`claimHitPoints`・`claimLongBonus`・`claimLongDistance` を追加。`DifficultyDef` に回数の範囲を追加。
    - 新規ファイル `customer.ts`（ロジック層）：出る時刻の決め方、状態の進み方、円柱と鍋の当たり判定を純関数で置く。
- **実装時の注意点・エッジケース**：
  - 当たり判定は `throw.ts` の細かい刻みの中で呼ぶ（速い鍋がすり抜けないように）。ただし `throw.ts` は客を知らない作りのままにし、当たったかどうかを返す判定を引数で渡す形にする。
  - 止まっている鍋（床に落ちている鍋）は命中にしない。
  - 客が出る前から窓の下に落ちていた鍋が、出現と同時に命中にならないようにする。
  - 中身の入った鍋を投げても、得点は同じ。中身は失われる（鍋は使用済みのまま）。
  - 2つ同時に投げて両方当たっても、命中は1回。
  - 一時停止中は、客の残り時間を進めない。
  - ゲーム終了の瞬間に客がいたら、何もせず消す（終了時に放置の扱いにしない）。
  - 鍋投げの得点は、1ゲーム最大90点（3回 × 30点）。パスタ1〜2皿ぶんに収まり、ランキングの主役は料理のままになる。
- **受け入れ条件**：
  - リーディングで5分遊ぶと、客が1〜2回出る。種を固定したテストで、出る時刻が60秒より後・280秒より前になる。
  - 飛んでいる鍋を当てると+20、4m以上なら+30、始末書が1増える。コンボは変わらない。
  - 12秒放置するとコンボが0になり、点は減らない。
  - 練習キッチンとチュートリアルでは客が出ない。練習用の的は、当てても点が入らない。
  - `customer.ts` の当たり判定と出現の決め方にテストがある。

### 4.8 クックのメニュー拡張（ハンバーグ・グリル系）

- **目的**：クック単独で5分遊べる品数（5品以上）にする。品を足すときに、コードの分岐ではなく表を足せばよい形にする。
- **現状の問題**：焼き皿の種類はドリア系とピザ系の2つで、必要な焼き時間は種類で決め打ち（ドリア = 下段の時間、ピザ = 上段の時間）。ハンバーグや小皿の前菜を足す場所がない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 新規ファイル `bake.ts` に「焼き物の表」を置く。1品につき次の項目を持つ：メニューの id、焼き皿の種類、取り出し元（どの冷蔵庫のどの棚か）、焼く前にのせる物と順番、必要な焼き時間（上段の何周ぶんか）、焼いた後の仕上げ（受け台、ソース、付け合わせ）、提供の形。
    - 焼き時間の決め方を、種類の決め打ちから、この表の値に変える。既存の2品は、表に同じ値を書いて挙動を変えない。
    - 焼き皿の種類を1つ足す：鉄板皿（ハンバーグ・グリル用）。外形の寸法はドリア系と同じにし、レーンと置き場の計算（3レーン）をそのまま使う。新しい置き方の決まりは作らない。
    - 第一弾の候補（工程は仮。下の「確認事項」を埋めてから確定する）：
      - ハンバーグ：鉄板皿にパティと付け合わせをのせる → 焼く → 木の受け台に乗せる → ソース1杯 → 提供

      - 半熟卵のドリア：ミラノドリアを焼いた後、卵を1つのせる（焼いた後の仕上げが1つ多い品）
    - 材料の置き場：今は空の3台目の冷蔵庫（`FridgeUnit` の2）と、具材台を使う。
  - UI/UXの変更点
    - 鉄板皿は、焼き上がりの後5秒、油のはねる小さな粒と音を出す。
    - 伝票の材料の行に、仕上げ（受け台・ソース）まで書く。
  - データ構造の変更点
    - `BakeStyle` に鉄板皿を追加。`layout.ts` の `BAKE_DISHES` に寸法を追加。
    - 手に持つ焼き皿（`Item` の `bakeDish`）に、どの品か（表の id）と、仕上げの進み具合を追加。
    - `MenuItem` の `form` に鉄板皿を追加。
- **実装時の注意点・エッジケース**：
  - 確認事項（かずまさんが実際の手順で埋める）：①各品の皿、流す段、焼き時間、②焼く前にのせる物と順番、③焼いた後の仕上げと受け台、④材料の保管場所（冷蔵・冷凍、どの台）、⑤1回に流せる枚数。
  - 焼け具合の判定（`bakeState`）は「必要な秒数ちょうどで焼き上がり、1.25倍を超えると焦げ」。品ごとの必要時間が上段の周回数で表せない値だと、どの段でも焼き上がらない品ができる。表の値は「上段の整数周」に限る、とテストで縛る。
  - 新しい品にも、チュートリアルの工程が必要（4.4と同じ）。
  - `oven.test.ts`（539行）と `pizza.test.ts`（704行）の期待値は変えない。焼き時間の決め方を変えても、既存の2種類の結果が同じになることを先にテストで固定してから直す。
- **受け入れ条件**：
  - 表に1行足し、材料の置き場とチュートリアルの工程を足すだけで、新しい焼き物が伝票に出て採点される（`game.ts` に品ごとの分岐が増えない）。

  - 既存のドリアとピザの焼け方が、変更前と同じ（既存テストが無修正で通る）。

### 4.9 手応えの演出とリザルトの内訳・称号

- **目的**：操作の結果を文字より先に動きで伝える。5分の結果を振り返れるようにする。
- **現状の問題**：取る・置く・提供が一瞬で切り替わる。リザルトは総合点だけ。
- **具体的な変更内容**：
  - 機能・挙動の変更点（演出は見た目だけ。ロジックは今までどおり即時に確定する）
    - 手持ち：歩くと上下に少し揺れる。持ち替えの瞬間に、0.1秒で1.08倍に膨らんで戻る。

    - 評価：難易度ごとの点数の区切りで S・A・B・C を付ける。区切りの値は `difficulty.ts` に置く（最初は仮の値でよい）。

### 4.10 画質設定

- **目的**：遅いPCでも遊べるようにする。
- **現状の問題**：画素比が端末まかせ（最大2）で、下げる手段がない。
- **具体的な変更内容**：
  - 機能・挙動の変更点
    - 3段階：低（画素比1、接地の影なし、映り込み弱、湯気と泡の数を半分）、標準（画素比は最大1.5、接地の影あり）、高（画素比は最大2、影の計算を1灯ぶんだけ有効、影の解像度1024）。既定は標準。
    - 開始から10秒の平均が1フレーム22ミリ秒を超えたら、「画質を下げると軽くなります」と1回だけ案内する。勝手には切り替えない。
  - UI/UXの変更点
    - iPad「設定」に「画質」を足す。
  - データ構造の変更点
    - `Settings` に画質の項目を追加。今の設定は数値のバーだけなので、選択式の項目を扱えるように、設定の定義に種類を足す。
- **実装時の注意点・エッジケース**：
  - 高の影は、据え置きの設備と台の上の器だけが落とす。手に持っている物は落とさない。
  - 画質を変えたら、その場で反映する（再読み込みを求めない）。
- **受け入れ条件**：
  - 低にすると、4.1で記録した場面③のフレーム時間が標準より短くなる。
  - 設定がブラウザに保存され、次回も同じ画質で始まる。

## 5. 全体の実装順序の提案

各手順を1つのプルリクエストにし、手順ごとに `npm test` と `npm run build` を通す。

3. **質感の土台**（4.1）：素材・環境の映り込み・トーンマッピング・接地の影。
4. **効果音と環境音**（4.5）：ほかと独立していて、体感の変化が大きい。
5. **鍋の焦げ**（4.6）：煙と音を一緒に入れられる。
6. **クックの採点接続とポジション選択**（4.4）：`firestore.rules` の貼り直し（手作業）を含む。
7. **厨房の作り込み**（4.2）：デシャップ窓までここで作る。
8. **料理と器の見た目**（4.3）：ドリアとピザが採点につながった後に仕上げる。
9. **クレーマー客イベント**（4.7）：窓（手順7）と音（手順4）がそろってから。
10. **手応えの演出とリザルト**（4.9）：始末書と焦がしの数が、ここで称号に使える。
11. **クックのメニュー拡張**（4.8）：実際の手順の確認が済んでから。
12. **画質設定**（4.10）、**名前ラベルの整理**（4.12）、**小ネタ**（4.11）。

## 6. 実装モデルへの引き継ぎメモ

### 特に注意してほしい点

- **ロジック層に Three.js を入れない**。新しい決まり（焦げ、客、焼き物の判定）は、`cfg` を引数で受け取る純関数とテストで書く。描画は状態を読むだけにする。
- **音・演出・客の見た目は「状態を見て動く」方式**にする。`game.ts` に、音や演出のための分岐やイベントの発行を足さない（チュートリアルと同じ設計判断）。
- **操作は `planInteract` の「できることを返す」形を守る**。ハイライトと実行が同じ分岐を通る、という前提を壊さない。
- **マテリアルを共有にするとハイライトが波及する**（4.1）。最初に直す。
- **見た目の違いを足したら `itemSignature` を更新する**。
- **`firestore.rules` はコンソールへの貼り直しが要る**。実装が終わったら、手作業が残っていることを明記して報告する。

### 既存コードとの整合性で気をつけること

- `layout.ts` の既存の座標と、`world.obstacles` を変えない。装飾は `interactables` にも `obstacles` にも入れない。
- `Target` と `Item` の既存の種類名を変えない（テストとチュートリアルの工程が名前で参照している）。足すのはよい。
- メニューを足したら、`tutorial.ts` の `RECIPES` と `difficulty.ts` の `menuWeights` も足す。
- 設定値は `config.ts` に足し、難易度で変える値は `difficulty.ts` の表で上書きする。関数の中に数値を直接書かない。
- ブラウザへの保存は、既存の接頭辞（`kitchen-time-attack:`）と、読めないときは既定値に戻す書き方に合わせる。
- 乱数は `Game` が持つ `rng` を使う（テストで種を固定できる）。`Math.random` を直接呼ばない。
- 仕様にない判断をしたら、README の「仕様にない判断」に1行足す（既存の習慣）。要件定義書の該当箇所（焦げ、ドリア枠、ピザ枠）も合わせて直す。
- 既存のテストは書き換えて通さない。仕様の変更で期待値が変わる場合は、どの決まりが変わったかを報告に書く。

### 避けてほしい実装方針

- 外部の3Dモデル（GLTFなど）や写真のテクスチャの導入。読み込みと容量が増え、今の「全部コードで作る」軽さがなくなる。
- 物理エンジンの導入。鍋の動きは、今の自前の計算を広げる。
- 画面全体にかける後処理（にじみ、陰影の後付けなど）。内蔵GPUで重い。
- ライトを増やして明るさを合わせること。明るさは、環境の映り込みと露出で合わせる。
- 毎フレームの形の作り直し。動きは、位置・回転・拡大縮小・テクスチャのずらしで表現する。
- `scene.ts` の一括の書き直し。切り出しは、マテリアル → 料理を作る関数 → 設備、の順に、見た目を変えずに少しずつ行う。
- 実在の店名・ロゴ・メニュー写真を、公開されるファイルに入れること。屋号は今のオリジナルのまま。
- ボケ要素で本編の操作を止めること（強制の演出、時間の停止、提供台をふさぐなど）。

### 未決事項（かずまさんの判断が要るもの）

- クックの各品の実際の手順（4.8の確認事項5つ）。
- オーブンの時間を30秒・60秒のまま本採用にするか。
- クレーマーのひとことの文と、称号の名前（どちらも表にまとめるので、後から差し替えられる）。
- 評価（S・A・B・C）の点数の区切り。何回か遊んだ点数を見て決める。
- 鍋投げの得点をランキングの点に含めるか（この設計では含める。最大90点）。
