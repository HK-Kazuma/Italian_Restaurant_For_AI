# 厨房タイムアタック

5分間で届く伝票をどれだけ多く・正確にさばけるかを競う、一人称視点の厨房タイムアタックゲーム（ブラウザ、PC専用）。
仕様は [イタリアンレストラン要件定義書.md](イタリアンレストラン要件定義書.md) を参照。

## 起動

```
npm install   # 初回のみ
npm run dev   # http://localhost:5173/
npm test      # ロジックの単体テスト
npm run build # 型チェック + 本番ビルド
```

## ランキング（Firebase Firestore）

ゲーム終了後、その難易度の自己ベストなら、結果画面から名前をつけて登録できる。みんなのランキングは、iPad の「ランキング」アプリで見られる（難易度ごと、上位10件）。
保存先につながる設定が空のあいだは「準備中」になり、ゲームはふつうに遊べる。保存先は [src/ranking.ts](src/ranking.ts) の中だけに置いてあるので、Supabase などへ替えるときは、そのファイルの `RankingBackend` の中身を入れ替える。

セットアップ（初回のみ）：

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作り、「Firestore Database」を作成する（本番モード）
2. 「ルール」に [firestore.rules](firestore.rules) の中身を貼って公開する（書き換え・削除は不可、追加できる内容は形・文字数・点数の範囲で制限）
3. プロジェクトの設定 → マイアプリ → ウェブアプリを追加し、`firebaseConfig` の `apiKey` / `projectId` / `appId` を控える
4. 手元で試す：`.env.example` を `.env.local` にコピーして値を埋め、`npm run dev`
5. 公開サイトで使う：GitHub のリポジトリ → Settings → Secrets and variables → Actions → **Variables** に `VITE_FIREBASE_API_KEY` / `VITE_FIREBASE_PROJECT_ID` / `VITE_FIREBASE_APP_ID` を登録し、Pages を再デプロイする

注意：これらの設定値はブラウザに入るので公開される前提で、守っているのは `firestore.rules`。改造すれば偽のスコアを送れるため、ルールの範囲内の不正までは防げない（友達内で遊ぶ規模を想定）。

## 開発ボード（iPad の「開発ボード」アプリ）

今後の開発予定を公開するアプリ。「開発中」「これから」の2つの一覧と、プレイヤーから開発者へ「実装してほしいこと」「改善してほしいこと」を送るフォーム（「要望を送る」タブ）がある。保存先はランキングと同じ Firebase Firestore（[src/devboard.ts](src/devboard.ts) の中だけ）。設定が空のあいだは「準備中」になる。

- 一覧を読む・要望を送る：誰でもできる
- 追加・「開発中／これから」の移動・削除：画面下の「🔒 開発者用」を開き、**開発者コード**を入力して行う（コードはブラウザに保存しない）
- 要望は `feedback` コレクションに溜まる。読めるのは Firebase コンソールだけ（アプリの中には出さない）

開発者コードの仕組み：コードは、一覧のデータ（`devBoard`）とは別の、誰も読めない `devAuth` に、同じバッチ書き込みで送られる。[firestore.rules](firestore.rules) が「同じバッチの `devAuth` の中身が正しいコードか」を見て、書き込みを許可する。ブラウザ側のコードにも、公開される一覧にもコードは入らない。

セットアップ（ランキングの設定ができていれば、これだけ）：

1. [firestore.rules](firestore.rules) の `DEV_CODE_HERE` を、決めた開発者コードに置き換える
2. **置き換えたルールは Firebase コンソールの「ルール」にだけ貼る**（本物のコードはリポジトリにコミットしない。リポジトリの中は `DEV_CODE_HERE` のまま）
3. コードを変えたいときは、コンソールのルールを書き換えるだけ（アプリ側の変更は不要）

注意：コードを誤って何度も試す攻撃を、ルールだけでは防げない。推測されにくい長めのコードにすること。

## 現在の範囲

要件定義書の開発ステップ1〜5まで。

- 実装済み：視点移動、スナップ方式の持ち運び、茹で麺器（4口）、伝票、5分タイマー、スコア・コンボ、鍋の循環（鍋置き場 → IH → 洗浄機で5秒洗う → 鍋置き場）。パスタは4品：たらこ（Bパターン）、ミート・パルマ風（Aパターン：ソース・具材を鍋に入れる（既定のソースになったら自動で加熱が始まる）→ 麺を鍋に入れる → 皿にかける → 粉チーズなど）、カルボナーラ（Bパターン：冷蔵庫下段のパックを熱湯で温めて鍋で加熱 → 麺を盛った皿にかける）。サラダは2品：小エビ・チキン（冷蔵庫上段のサラダベースをサラダ台に置き、具材を載せ、ドレッシング・パプリカパウダーのボトルを右クリックでかけて、左の提供台へ）。冷蔵庫の扉は最初は閉まっていて、視点を合わせて右クリックで開閉。ペンネアラビアータ（冷蔵庫のペンネを茹で麺器へ、トマトソース・ガーリック・唐辛子を鍋に入れて加熱、パセリ）、ほうれん草のソテー（冷蔵庫のトレーをサラダ台に置き、トングで2掴み、パンチェッタ・ソテーソースと加熱、小皿に盛る）、コーンスープ（パックを最大5つ持って熱湯3×3の9か所に浸け、温めてスープ皿に入れる）。ペペロンチーノ（Bパターン：冷蔵庫の塩オイルソースのケースをサラダ台に置き、1杯・ガーリック・唐辛子を鍋に入れて加熱、麺を盛った皿にかけ、パセリ）。混ぜる動作（麺を入れた鍋を、IHの上で左クリック3回）
- チュートリアル：練習キッチンの iPad の「チュートリアル」アプリを開くと、いまあるメニューがすべて並ぶ（`MENU` から自動生成）。練習したいメニューをタップすると、厨房が最初の状態に戻り、作り方を黄色い矢印（3D）と左の工程一覧（↓でつなぐ）で順番に案内する。工程は `src/tutorial.ts`
- 未実装：ソースの焦げ（鍋の加熱は「完成」で止まる）、音と演出（手順9）
- メニューは `src/recipe.ts` に15品定義済みで、すべて `enabled: true`（false にすると、その品は伝票に出ない）。要件定義書の冒頭は「9品」のまま（ペペロンチーノ・イカスミ・きのこのクリーム・サラダ3品が増えたため）

## 読解ガイド

### 読む順序

1. [src/config.ts](src/config.ts)：調整パラメータの全部。リアルモードはここを差し替える
   - [src/layout.ts](src/layout.ts)：冷蔵庫・サラダ台・熱湯の置き場所（座標）。手で位置を調整するときはここ
2. [src/types.ts](src/types.ts)：`Item`（手持ち）、`Target`（クリック先）、`GameState`。データの形がここで決まる
3. [src/recipe.ts](src/recipe.ts)：9品のレシピと `judge()`（皿の中身とレシピが一致するかの判定）
4. [src/boiler.ts](src/boiler.ts)：茹で麺器の状態遷移（`empty → set → boiling → lifted → overdue → shortBoil`）
5. [src/tickets.ts](src/tickets.ts) と [src/score.ts](src/score.ts)：伝票の届く間隔と、得点の計算
6. [src/pot.ts](src/pot.ts) と [src/pack.ts](src/pack.ts)：鍋の状態（具材を入れる・加熱・皿にかける）、洗浄機、熱湯で温めるパック
7. [src/game.ts](src/game.ts)：全体の統合。`planInteract()` が「この手持ちでこの設備をクリックしたら何が起きるか」の表
   - [src/tutorial.ts](src/tutorial.ts)：チュートリアルの工程。メニューごとに「矢印の指す先」と「終わったか」を並べたもの。`game.ts` が毎フレーム読んで進める
8. 描画と入力の層
   - [src/scene.ts](src/scene.ts)：厨房の3Dシーン。状態を読んで見た目に反映する
   - [src/interaction.ts](src/interaction.ts)：画面中央のレイキャストと、操作できる設備のハイライト
   - [src/input.ts](src/input.ts) / [src/player.ts](src/player.ts)：PointerLock、クリック、視点・移動
   - [src/hud.ts](src/hud.ts) / [src/main.ts](src/main.ts)：表示と、起動・メインループ

データの流れ：

```
入力(input.ts) → 狙っている設備(interaction.ts) → Game.interact()（game.ts）
  → 手持ち・鍋/皿・麺器の状態を更新 → 提供で judge()（recipe.ts）→ score.ts → state
state → scene.ts（3D）/ hud.ts（DOM）が毎フレーム読んで表示
```

### 学びポイント

- **ロジックと描画の分離**：`game.ts` までは Three.js を一切使わない。そのため、ブラウザなしでテストできる（`src/*.test.ts`）
- **操作をクロージャで返す設計**：`planInteract()` は実行せずに「できること」を返す。ハイライトの判定と実行が同じ分岐を共有するので、「光るのにクリックで反応しない」という食い違いが起きない
- **状態を書き換える純関数**：`boiler.ts` の各関数は「遷移できたら true」を返す。遷移の条件が1か所にまとまる
- **差分があるときだけ作り直す**：皿や手持ちの3Dモデルは、中身の署名文字列が変わったときだけ作り直す（`scene.ts` の `ItemView`）
- **設定値の注入**：各関数は `cfg` を引数で受け取る。テストで値を差し替えやすく、リアルモードもこの形で作れる

### 設計判断

1. **見た目はプリミティブの箱**：モデルの差し替えは手順9で行う前提で、今は動作の確認を優先した。代替案は、最初からKenney等の素材を取り込むこと。ダウンロードと整合の手間が先に立つので見送った
2. **皿の中身は `IngredientId[]` 一本**：要件定義書どおり「入れる・かける・移す」をすべて追加として扱うので、メニューが増えても分岐が増えない。代替案はメニューごとの専用クラス。9品に増えると破綻する
3. **クリックとダブルクリックを分けない**：クリックは常に実行し、2回目だけ追加でダブルクリック処理を呼ぶ。素早く別の設備を押す操作が、ダブルクリック扱いで取りこぼされないようにするため
4. **チュートリアルは「ゲームの状態を見て進める」**：工程の終わりは、`GameState` だけで決まる判定（`done`）にした。`game.ts` の操作側には、チュートリアル用の分岐を1つも入れていない。代替案は、操作のたびにイベントを出して工程を進める方式。こちらは操作を足すたびにイベントも足す必要があり、チュートリアルとゲームが食い違いやすい。状態を見る方式なら、順番を飛ばして先の工程を済ませても、まとめて進める（戻りはしない）

## 設備の位置を調整するとき

冷蔵庫・サラダ台・熱湯の位置は [src/layout.ts](src/layout.ts) の座標で動かせる（上から見た x / z、単位 m。プレイヤーが立つ場所が (0, 0)、+x が右、-z が奥）。保存すると開発サーバーが自動で読み込み直す。

- **手が届かなくなったら、設備を近づけて調整する**：手が届く距離は [src/config.ts](src/config.ts) の `reach`（今は5m）。プレイヤーは壁ぎわまで歩けるが、設備の位置によっては手が届かなくなる。届かないときは、設備をプレイヤー側へ近づける。どうしても離したいときだけ `reach` を伸ばす（伸ばすほど「歩かずに全部に手が届く」という設計から離れる）
- **視線が遮られていないか確認する**：冷蔵庫の角や、手前の設備が、奥の物への視線を遮ることがある。冷蔵庫を動かしたあとは、サラダ台の奥の具材（小エビなど）を、プレイヤーの初期位置から狙えるか確認する
- **端を合わせるときは範囲を見る**：各設備の占める範囲（例：サラダ台は x±0.55、z±1.35）は `layout.ts` の先頭に書いてある。熱湯の右手前の端に、サラダ台の左手前の端を合わせるなら、サラダ台の x = 熱湯の x + 1.0、z = 熱湯の z - 0.85
- **部屋の壁は自動で広がる**：設備が壁からはみ出すときは、右と奥の壁・床・天井が広がる。左と手前は広がらない
- **歩ける範囲**：壁の内側で、設備の中には入れない（体の半径 `playerRadius` 0.3m）。設備の当たり判定は `scene.ts` の `obstacles`（冷蔵庫・サラダ台・熱湯は `layout.ts` に追従する。IH・茹で麺器・左の台は座標を直接書いてある）
- **動かせるのは3つだけ**：左の台・IH・茹で麺器などは、まだ座標を `layout.ts` に出していない（`scene.ts` の中に直接書いてある）

## 仕様にない判断（要件定義書へ反映するか要確認）

- 空の皿を提供台に出した場合は、減点なしで「空の皿は出せない」と表示する
- 同じ料理の伝票が複数あるときは、最も古い伝票が消える
- 皿の中身は個数まで一致すれば、盛る順序は問わない
- `Ticket` 型にレール表示用の `id` を足した
- スコアは0未満にならない
- 鍋に具材を入れた時点で「使用済み」になる。使用済みの鍋は洗浄機に入れるまで鍋置き場へ戻せない
- 皿にかけ終えた空の鍋は、洗うまで具材を入れ直せない
- ソースは加熱前だけ、麺は加熱完了後だけ鍋に入れられる。皿にかけられるのは加熱完了後の鍋だけ
- 加熱が進むのは、鍋がIHに載っている間だけ（持ち上げると止まる）
- 缶のお玉は手に持てる1つ分（2杯入れるには缶と鍋を2往復する）
- 冷蔵庫を右（IHから右へ90度）に置き、サラダ台のプレースホルダーを奥へ寄せた。トッピングは台の奥の列（たらこ・のり・粉チーズ・パセリ）に移した
- クリックで手に取れる場所（缶・パック・トッピング・パンチェッタ）は、すべて同じ `stock` として扱う。手に持つ物は種類で変わる（ソースはお玉、パンチェッタはトング、カルボナーラは温めが要るパック）
- 熱湯に浸けた時間は累計で数える。途中で取り出して戻しても、続きから温まる（冷めない）
- 温まっていないパックは鍋に入れられない
- トマトソースは「パック1つ」で1杯分とみなす（要件定義書は「トマトソース1杯」、取り出し元は冷蔵庫の容器に変更）
- 熱湯はサラダ台とIHの間に置いた（要件定義書は「茹で麺器の左」）。サラダ台は奥へずらした
- 台の奥の列に、ブラックペッパーを追加した
- 右クリックは、冷蔵庫（扉・中の物）に視点が合っているときは扉の開閉、それ以外は手に持っている物を捨てる。冷蔵庫に視点が合っていると、扉の開閉中でも手の物は捨てない
- 扉が閉まっている間は、冷蔵庫の中の物は取れない。左クリックでは開かない（案内が出る）
- サラダベースは「皿にサラダが入ったもの」として、皿と同じ扱い（中身 `saladBase` の皿）。サラダを作る台は、皿の置き場の続き（`saladSlotCount`、今は2か所）
- サラダ台の幅を広げ、具材コーナーに小エビ（お玉）・チキン（トング）・パンチェッタ（トング）・ドレッシング・パプリカパウダー（ボトル）を置いた。パプリカパウダーはレシピに必要なので追加した
- サラダの提供は、パスタと同じ左の提供台（要件定義書のとおり）
- 冷蔵庫・サラダ台・熱湯の置き場所は [src/layout.ts](src/layout.ts) の座標で決める（上から見た x / z、単位 m）。位置関係と向きは変えず、基準点だけを動かす。今は、サラダ台の左手前の端を熱湯の右手前の端（x=2.4, z=-1.3）に接するよう合わせ、冷蔵庫も同じだけ動かしてある。このため冷蔵庫はプレイヤーの真横（z=0）より0.6m奥になる
- 鍋の中身は見た目で分かる。ソースは量に応じた高さの液面（ミートソースはお玉1杯で半分、2杯で満杯。`pot.ts` の `SAUCE_FILL_PER_UNIT`）、ミートソースはひき肉のかたまり入り、パンチェッタは細切れのベーコンがバラバラ（入れた順序に関係なく、いちばん上に見える）、麺は中央の山（まわりにソースが見える）
- 複数のソースを入れたときは、量で重みづけした色に混ざる。パンチェッタだけが底に少量あるときは、見えるよう高めの山にしている
- 皿の上のパンチェッタも、鍋の中と同じ細切れの見た目にした
- IHにボタンはない。鍋の中身が既定のソースと一致したら、自動で加熱が始まる（ミートソースはお玉2杯、パルマ風はトマトソースとパンチェッタ、カルボナーラは温まったパック。入れた順序は問わない）。既定の組み合わせは `recipe.ts` の各メニューの `sauce`
- 既定のソースにならない組み合わせ（例：ミートソース+トマトソース）は加熱が始まらず、IHのラベルに「組み合わせ違い」と出る。やり直すには、鍋を洗浄機で洗う
- ソースの材料が、別のソースの材料の一部になる組み合わせは作らない（入れている途中で先に一致して、加熱が始まってしまうため。`recipe.test.ts` で確認している）
- 湯気（[src/steam.ts](src/steam.ts)）：IHで加熱中の鍋は、進むほど湯気が増え、完成でいちばん多くなる（焦げの手前で、画面を見なくても気づけるようにするため）。茹で麺器は、茹でている間は多く、そのほかも弱く出る（お湯は温かい）。熱湯も弱く出る。一時停止中は止まる。ラベルは湯気より手前に描く
- ドレッシングとパプリカパウダーは、取り出し元ではなく「ボトル」。左クリックで持ち、サラダの皿に視点を合わせて右クリックで、かける・振る（ボトルは手に残るので何度でもかけられる。かけすぎると注文ミス）。ボトルは捨てられず、サラダ台の天板の好きな場所に、左クリックで置く（置く前に、置こうとしている場所へ輪と薄いボトルが出る。ほかのボトルに近すぎると赤）。最初の置き場所は `layout.ts` の `BOTTLE_HOME`
- パセリもボトルにした（ドレッシング・パプリカパウダーと同じ。左クリックで持ち、皿に視点を合わせて右クリックで振る）。置ける台は、ドレッシング・パプリカパウダーはサラダ台だけ、パセリは左の台（皿・トッピングの台）にもサラダ台にも置ける。かけられる皿は、ドレッシング・パプリカパウダーはサラダの皿だけ、パセリはパスタの皿（左の台）だけ。置けない台に視点を合わせると、赤い輪と「このボトルは、この台には置けない」が出る。ボトルごとの決まりは `src/bottle.ts`、台の大きさと最初の置き場所は `layout.ts` の `SURFACES` / `BOTTLE_HOME`

- 熱湯は3×3の9か所（`config.ts` の `hotWaterColumns` / `hotWaterSlotCount`）。温めるのはカルボナーラ（3秒）とコーンスープ（5秒）。コーンスープのパックだけ、クリックした回数だけ最大5つまで手に持てる（`cornSoupStackMax`）。手に持てるパックは同じ種類だけ
